Activity Brief

This activity explores gradient descent and the cost function used to optimise machine-learning models. It involves reading the Mayo (2017) article and running the gradient_descent_cost_function.ipynb tutorial, modifying the number of iterations and the learning rate to observe how these parameters influence the reduction of cost.

The initial programme execution, experimental changes to iteration counts and learning rates, observations of cost reduction and a reflection on the findings will be documented in this section of the e-Portfolio. The activity also prepares the findings for discussion during the unit seminar.

The activity addresses the following learning outcomes.

  • Understand the applicability and challenges associated with different datasets for the use of machine learning algorithms.
Baseline Execution

The analysis fits ŷ = mx + b to five observations: x = [1, 2, 3, 4, 5] and y = [5, 7, 9, 11, 13]. These points lie exactly on y = 2x + 3, providing a known solution against which to check optimisation. The cost is mean squared error, J(m,b) = (1/n) Σ(y − ŷ)², with no factor of one-half.

The baseline starts from m = 0 and b = 0, uses learning rate α = 0.08 and performs 100 updates. Both gradients are calculated at the same parameter values before either parameter changes: ∂J/∂m = −(2/n) Σx(y − ŷ) and ∂J/∂b = −(2/n) Σ(y − ŷ). Each update subtracts the learning rate multiplied by the respective gradient. All five observations contribute to every update, making this full-batch gradient descent.

Mayo (2017) explains how gradients guide weight updates and distinguishes batch, stochastic and mini-batch training. Here, the slope and intercept are updated using the full dataset. Their derivatives are calculated directly; there is no multilayer network requiring backpropagation. More precisely, backpropagation computes gradients through a network, while gradient descent uses those gradients to update parameters. The article’s discussion of local minima does not apply to this strictly convex quadratic.

Reporting Accuracy

The reference programme prints updated parameters alongside cost calculated before that update. Its last printed line therefore reports 0.004120600 from 99 completed updates beside the parameters after 100 updates. Recomputing cost at those parameters gives 0.003900707. The portfolio tables align every cost with the displayed parameters and use completed-update counts rather than zero-based loop indices.

The original code was replayed and its final parameters checked against the aligned implementation. Finite-difference checks confirm the gradients, and an independent least-squares calculation returns m = 2, b = 3. The cost is strictly convex in these two parameters, so this dataset has a unique global minimum of zero.

Convergence Behaviour

Cost falls from 89 initially to 9.691269 after ten updates, then to 0.003901 after 100. At 500 updates it is approximately 1.160e−12, with parameters close to the exact solution. At 1,000 updates the remaining error is negligible for this example. Values displayed as 2.000000 and 3.000000 are rounded, not claims of mathematically exact convergence.

The learning curve shows rapid initial improvement followed by progressively smaller reductions. Parameter values can alternate across the optimum while the cost still decreases. This distinction matters: overshooting in parameter space does not necessarily imply divergence. Further iterations are useful only while the update remains stable and the remaining optimisation error matters.

An iteration limit controls computation but does not establish convergence. A stronger stopping rule would combine a maximum budget with a gradient-norm or cost-change tolerance. These results describe fitting five noiseless points; reducing training cost does not demonstrate predictive performance on independent data.

Why Larger Steps Can Fail

Rate 0.08 gives the lowest cost among the tested rates at this budget. Increasing the rate to 0.084 produces a much higher cost despite remaining within the convergence range: the iterates alternate with weak damping. At 0.085 the cost exceeds its initial value and grows; at 0.1 it reaches approximately 1.114e29. Extra iterations cannot repair an unstable fixed step size.

For this quadratic cost, the curvature matrix is H = [[22, 6], [6, 2]], with eigenvalues approximately 0.338096 and 23.661904. The parameter error evolves as e_next = (I − αH)e. Convergence from any starting parameters requires 0 < α < 2 / λ_max(H), giving a strict upper limit of approximately 0.084524. This explains the observed difference between 0.084 and 0.085.

The bound is specific to these features and this MSE normalisation. Rescaling the predictor, changing the dataset or using a half-MSE objective changes the gradients and the permissible step sizes. The experiment therefore supports checking the cost trajectory and curvature rather than treating a particular rate as universally appropriate.

Reflection

Mayo’s (2017) account of step size provides a conceptual starting point; the experiments establish its effect for this particular cost function. Iteration count and learning rate address different aspects of optimisation. More updates reduce the remaining error for a stable run, but amplify divergence when the rate is too large. The contrast between 0.08, 0.084 and 0.085 also shows that the largest stable rate need not give the best finite-budget result. The explicit stability calculation makes these outcomes explainable rather than relying only on trial and error.

Accurate reporting is equally important: the parameter values and cost must refer to the same update. For problems where a safe fixed rate is unknown, a step-size procedure that checks sufficient decrease offers a principled alternative to accepting every proposed step (Armijo, 1966). Optimisation choices also depend on computational cost, curvature and data scale, which become more consequential in larger learning problems (Bottou, Curtis and Nocedal, 2018).

This example uses exact full-batch gradients on a noiseless, strictly convex problem. It does not test noisy estimates or stochastic updates, whose foundations and convergence conditions differ (Robbins and Monro, 1951). The near-zero cost confirms recovery of the known line, not real-world generalisation. A broader evaluation would examine scaling and noisy data, use explicit stopping criteria and assess predictions on independent observations.
